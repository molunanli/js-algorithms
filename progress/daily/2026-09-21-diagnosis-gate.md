## §1 定级禁令裁定

### 1.1 结论

**在零作答、零代码证据的情况下，`mastery` 不得写入任何等级，包括不得写 `L0`。**

### 1.2 规则出处

| 出处 | 原文要点 | 对本裁定的支撑 |
|------|---------|--------------|
| `掌握度评估标准.md` §一 | 「L0 未接触＝该模块**没有学习痕迹**，需要证据：**无练习文件、答卷空白**」 | L0 也是**需要证据**的等级，不是「默认值」 |
| `掌握度评估标准.md` §3.2 | 禁止「基本掌握／差不多／有进步」等模糊结论 | 无证据即无法给出确定等级 |
| `掌握度评估标准.md` §3.3 | 硬性判定口径均以「代码能否运行／用例是否通过／复杂度是否达标」为准 | 等级只能由**作答产物**推出 |
| `掌握度评估标准.md` §3.6 | 每次等级变动须留 `evidence`（文件:行号 / 题号得分）与 `reason` | **无 evidence 的等级写不进合规档案** |
| `需求书` §4 通则 1 | 阈值必须「可数、可复核」 | 零作答时所有计数均为「未测」，非 0 分 |
| `需求书` §5.2 第 5 条 | 「**无证据即无效**：任何等级判定若不能落到证据形式，该判定作废」 | 直接禁止本次定级 |
| `需求书` §8.3 | 「未考模块 `mastery` 中**不写入**」 | 未测模块一律不写 |

### 1.3 「L0 证据＝答卷空白」与我方裁定的关系（关键澄清）

《掌握度评估标准.md》§一 把「答卷空白」列为 L0 的**证据**。本裁定与之**不冲突**，因为二者前提不同：

| | 前提 | 是否可定 L0 |
|---|------|------------|
| 标准所指 | 题目**已交付**、学习者**已在作答**、**实际看过该题**后留空 | 可作为 L0 证据 |
| 本裁定所指 | 学习者**尚未开始作答**，无任何尝试产物 | **不可**定级（无证据） |

→ 适用规则：**只有在「该模块题号被实际作答（含显式标注）」之后，才谈得上按证据定级；作答之前一律为「未测」。**

### 1.4 「未接触」与「证据不足」的区分与确定写法

两者都必须**先有作答动作**（进入过该题），再按下列口径落库：

| 情形 | 定义 | 是否可判定 | `progress.json` 确定写法 |
|------|------|-----------|------------------------|
| **A. 未测（untested）** | 本轮全卷未作答／该模块整场未做（如放弃探测场） | **否**，不得定级 | **不写入 `mastery`**（依 §8.3）；在日报单列「未测清单」 |
| **B. 未接触（L0，可采信）** | 已作答该题，且学习者**显式标注「未接触／不会」** | **是**，可记 `L0` | `"level":"L0"`，`reason` 注明「**依据学习者显式标注『未接触』，非能力实测**」，`evidence` 引用该标注所在 `quizzes/2026-09-21-baseline.md#Qx` 行号 |
| **C. 证据不足（insufficient-evidence）** | 已作答该题但**静默留空**（无标注），或该模块题组**部分缺答** | **否**，不得定级 | **不写入 `mastery`**；日报记「证据不足（缺 Qx）」，附缺答题号 |

**为什么 B 可判 L0、C 不可**：
- B 中「未接触」与 L0 的定义（「没有学习痕迹」）**语义完全重合**，且标准已认可「答卷空白」作为 L0 证据，故 B 属**可采信的弱证据**；
- C 中静默留空**无法区分**「不会」与「没时间／漏做」，二者对应的等级完全不同（前者 →L0/L1，后者 →未测），故只能记「证据不足」，**不得**向下取默认 L0（那是放水）。

**红线**：**不得**用「静默留空」倒推 L0，**不得**把自述区里「我学过但忘了」当成任何模块的等级依据（`需求书` §7：自述区**不参与等级判定**）。

### 4.6 **必须叠加的模块级硬门槛（防止用题内得分放水）**

教师版判分点给的是**题内计分**；模块等级还须叠加下列硬门槛（`需求书` §4 通则 3、4，`掌握度评估标准.md` §一.2、§一.3）：

1. **任何一组隐藏边界用例失败 → 该模块本次 ≤ L2**（无论题内得分多高）。
2. **复杂度未达题目要求 → 该模块本次 ≤ L2**（例如 Q4 未达 O(1) 空间、Q7 未达 O(n)、Q10 未达 O(log n)、Q11 未达 O(1) 空间）。
3. **需要提示才写对 → 降一级**（基线原则上不给提示；若给过，按降级处理）。
4. **代码无法运行 → 该题 0 分**，其所属模块相应降级。

## §5 答卷 → 定级的证据交接清单

### 5.1 受理前提（任一不满足即退回）

### 5.2 逐题证据清单（必须逐条落库）

| 项 | 要求 |
|----|------|
| 题目编号 | Q1–Q11（及子问 6a/6b、7a/7b、8a/8b、9a/9b、10a/10b、11a/11b） |
| 文件路径 | `exercises/{模块编号-模块名}/2026-09-21-{slug}.js`（确切到文件） |
| 行号 | 关键实现行（如 Q5 缺陷行）与文件头五字段注释位置 |

| 实际输出 | 贴实跑 stdout；**空输出＝断言全过** |
| 期望输出 | 题面示例用例 + 判分点定义的隐藏边界用例 |
| 边界用例 | 是否通过、覆盖了「空/单元素/全相同/极值」的哪几类 |
| 复杂度 | 是否达标（对照题面约束：Q3 O(n)、Q4 O(1) 空间、Q6 O(n)、Q7 O(n)、Q10 O(log n)、Q11 O(1) 空间） |
| 提示记录 | 该题是否给过提示（影响是否降级） |

### 5.3 **判「能独立（L3）」必须核实的 5 件事**（代码题）

1. **代码可运行**：`node` 实跑无语法/运行错误。
2. **示例用例全过**：题面给出的用例断言全过。
3. **隐藏边界全过**：判分点清单里「未在题面出现」的边界用例断言全过（这是 L3 硬门槛）。
4. **复杂度达标**：与题面约束一致（复杂度不达 → 最高 L2）。
5. **断言真实存在**：文件中**确有 `console.assert` 等可执行断言**——**防止「文件里没有断言 → 跑起来无输出 → 被误判为全过」的伪通过**。此条为本次新增防伪项，务必核实。
6. 叠加：**无提示使用记录**（有 → 降一级）。

### 5.4 文字题（Q1/Q2/Q5/Q7b/8b/9b/10b/11b）证据

引用 `quizzes/2026-09-21-baseline.md` 的**确切行号**，按教师版**判分点逐点计数**，**不给整体印象分**。

## §10 历史代码证据采信规则（v1.2，2026-09-21）

> **触发**：目标远端仓库发现学习者本人 2026-09-17～09-18 的两份真实代码（`01-js-basics/01-two-sum/solution.js`、`01-js-basics/containsDuplicate/solution.js`）。本规则**在 code-reviewer 实测结论之前**先行制定，以避免「看着数据改规则」这一最易放水的环节。
> **效力**：本节为 level-diagnostician 的正式裁定，**为追加内容，原 §1–§9 一律不改**。（因 §9 已被「红线复述」占用，本条顺延为 **§10**。）

### 10.0 一句话结论

**历史代码 = 旁证（side-evidence），不是直接定级证据。**它**不写入、不上调、也不否定**任何 `mastery.*.level`；只用于方案编排，并阻止把「有学习痕迹」误标为 L0/未接触。

### 10.1 裁定一：证据地位（明确二选一 → 旁证）

**结论：旁证，非直接定级证据。**

**新增条款**（《掌握度评估标准.md》**无**对应条款，本条为**本次新增**，建议后续并入该文件 §一，作为「§一.6」）：

> **§一.6（新增）历史/非闭卷代码的证据地位**
> 写于既往时间、非闭卷、独立性不可验证、但内容可复核的代码（下称「历史代码」）**一律记为旁证**，**不得作为直接定级证据**——不得据其在 `mastery.*.level` 写入或上调任何等级。
> **理由**：L0–L4 各级均以「学习者在**受控条件下**表现出的能力」为定义（L1「自己写不出来」、L2「能照模板写出」、L3「**独立**写对」、L4「能迁移」），且 §一.4 规定「需要提示的答案降一级」——**独立性是等级定义的内含要求**。历史代码的**独立性不可验证**（可能查过题解/照抄），故不满足定级的充分条件。
> **合法用途**：① 方案编排（起点讨论、节奏与难度预判）；② 复习队列冷启动参考；③ 生成**待验证假设**，交由闭卷卷面证实/证伪。
> **双向约束**：旁证**不得上调**任何等级；**亦不得反向歧视**——当闭卷卷面**已证明**某等级时，不得以「那只是抄的/历史代码」为由拒绝承认。

### 10.2 裁定二：接入 L0–L3 证据框架

| 等级 | 历史代码能支撑到哪一级 | 止步点 |
|------|----------------------|--------|
| **L0** 未接触 | **可否证**：存在代码＝该模块**有学习痕迹** → **不得标 L0/未接触**（仅限该模块） | — |
| **L1** 能识别 | 可**部分**提示（能写出可运行解，行为上已高于「只看懂」） | 不作定级依据 |
| **L2** 能复现 | **不足**：无法证明独立性（可能照抄题解） | **止步于「疑似」** |
| **L3** 能独立 | **不可**：独立性不可验证；且历史解**无变式/边界/复杂度解释**的受控证据 | **硬止步** |
| **L4** 能迁移 | **不可** | — |

**两个硬止步点（务必记住）**：
1. **能证明「会写」≠ 能证明「独立会写」** → 无法越过 L2→L3 的独立性门槛；
2. **写代码 ≠ 会复杂度分析** → 历史解即便最优，也**不能**支撑 M01 的「**推导**」能力（M01 的 L3 要求写出推导过程）。

### 10.3 裁定三：对起点判定的影响（复核 team-lead 判断）

**结论：team-lead 判断成立——起点不会、也不应因历史代码前移。** 补充三条理由：

1. **规则层**：历史代码不产生 `level`（§10.1），故对 §8.3 的 `currentModule ＝「已考基础层中最低的未达 L3 模块」` 公式**无任何输入**；`currentModule` 只吃**闭卷卷面**结果。
2. **学理层（前置约束）**：即便历史 M04 疑达 L3，起点仍应取 M01/M02——`算法知识大纲.md` 明确规定 **M04 前置 M02，M02 前置 M01**；而 M01（复杂度**推导**）、M02（**变式/边界**）**无闭卷证据**，跳过前置＝**高估失真**（§1.3）。
3. **唯一合法的「前移」路径**：**由闭卷卷面驱动**——**若且仅若**闭卷卷面证明 **M01 达 L3（推导完整）且 M02 达 L3（变式+边界全过）**，起点才自然前移至 M03/M04（§8.3 公式的自然结果）。**仅凭历史代码，不得前移。**

→ 若坚持前移，**最低门槛同上**（M01 且 M02 闭卷达 L3）；达不到即不得前移。

### 10.4 裁定四：Q7a 是否改题

**结论：不改题，保留原 Q7a。** 理由：

1. L3 的定义是「能**独立**写对」，与「3 天前是否写过」无关；**闭卷复现本身即有效证据**（甚至更严）。
2. 历史代码是**旁证**、不进 `mastery`，且**学习者版卷面无答案**（§3.2）→ **不存在「Q7a 被答案泄漏而失效」**的问题。
3. **真正的风险是「记住答案」而非「泄漏答案」**：历史 Map 版与 Q7a 同构，可能「背出满分」。此风险**已由 Q7b 兜底**——Q7b 考「额外空间代价 + `Object` 键陷阱」属**理解题**；且 §4.3 已规定 **M04 达 L3 必须 7b 得「空间代价」2 分** → **仅 Q7a 满分到不了 L3**。故**无需改题**。
4. **可选加固（非必须，交 quiz-architect 决定）**：把 Q7a 的**隐藏边界**换成「历史代码未覆盖」的用例（如空数组 `[], 7` → `[]`、目标不存在 → `[]`），进一步压低「背题」命中率。**不得**为此降低原题严格度或调整判分点权重。

### 10.5 裁定五：evidence 引用格式（可复核）与落库位置

**确定引用格式**：

```
repo@<full-sha>:<path>:<startLine>-<endLine>
```

示例：`repo@0d7ffa4:01-js-basics/01-two-sum/solution.js:1-30`

**复核命令（任何人可复现）**：

```bash

```

**必须附内容指纹**（抗 SHA 丢失/改写）：`sha256:<前12位>`（对 `git show <sha>:<path>` 的完整输出计算）。

**落库位置（关键）**：旁证**不进** `mastery.*.evidence`（那是**等级证据**字段），也**不进** `history[]`（那是**等级变动**记录）。改为写入**新增旁证区** `sideEvidence[]`：

```json
"sideEvidence": [
  {
    "module": "M04 哈希表",
    "ref": "repo@0d7ffa4:01-js-basics/01-two-sum/solution.js:1-30",
    "sha256": "…12位…",
    "observedAt": "2026-09-17~18",
    "recordedAt": "2026-09-21",
    "admissible": true,
    "note": "旁证：Map 单次遍历求补数；不用于定级，仅编排参考"
```

**向后兼容**：`sideEvidence` 为**可选顶层键**；`progress.py` 只读取已知键、保存时**原样保留**未知键，故兼容（同 §6.5 结论）。

**可复核性门槛（硬性）**：旁证**必须可复核**才可采信。
- **可复核**：能由上述 `git show` 命令重现（或将对象另存副本 + 附 `sha256`）；
- **不可复核**（对象丢失/被改写/无法重现）→ **不作为旁证采信**，状态记「**疑似旁证，不可复核**」，**不写入 `sideEvidence`**、不进方案。

### 10.6 四种状态的定义（含新增「有旁证」）

| 状态 | 含义 | `mastery` 写法 | 旁证区 |
|------|------|---------------|--------|
| **未测** untested | 未作答 / 整场未做 | 不写入 | — |
| **未接触** untouched | 作答时**显式标注**未接触/不会 | `level:"L0"`（弱证据） | — |

→ 与 §1.4 的 A/B/C 对应：A=未测、B=未接触、C=证据不足；本处**新增 D=有旁证**。
